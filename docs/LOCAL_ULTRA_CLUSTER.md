# Phone-free local Ultra cluster

`headunit-cluster-wayland --local-ultra-profile FILE` starts the verified signed
cluster on the existing backup background layer, with the authored 1920 × 720
canvas and an explicitly named output. The installed appliance opts in through
`pre_phone_gauges`. A build without the complete signed GPU receiver keeps its
ordinary native instruments.

This owner uses local monotonic animation time and original dated vehicle
observations. Its required `iPhoneVideo` slot is empty: no decoder, transport,
phone frame, phone clock or UI-Sync session is created. Display activation
starts the local resume scene. It does not assert ignition, authentication or
phone readiness. Real compositor presentation receipts date first visibility;
local redraws are not fresh phone frames. Missing vehicle readings remain
unavailable, and the configured warning overlay consumes the same dated samples.

The connected presenter remains the existing foreground owner above the backup
layer. This layer arrangement is source behavior; connected handover and physical
fault recovery need separate phone/display qualification. A local startup or
rendering exception destroys its GPU/VM resources before the caller resumes the
ordinary native cluster.

## Saved selection admission

When `persistClusterLayout=true`, the local owner preloads the same private,
verified pack/version-scoped confirmed record as the connected layout owner.
The disk worker enforces its existing bounded regular-file, ownership, mode and
directory checks. The local owner does not read a live button request or write
back an unconfirmed local choice.

Before starting the display VM, an isolated bounded metadata VM checks saved
layout IDs against primary layouts declared for `Cluster_Display`. A malformed,
unknown, nonprimary or foreign-display cached layout preserves the configured
signed startup layout. An empty configured layout preserves the asset's own
default. A valid saved layout can restore an existing matching palette;
unknown/mismatched palette metadata leaves the palette to the signed asset.
Invalid configured defaults or invalid signed metadata still reject local
startup and expose native instruments.

The former path replaced the configured layout before checking its catalogue.
A well-formed unknown cached ID then faulted the actual display VM instead of
using the compatible configured default. Metadata validation now happens before
the rendering owner starts, and rejected cached palettes cannot leak into the
default selection. Primary-layout admission does not independently qualify all
styles, palettes or disconnected centre content.
